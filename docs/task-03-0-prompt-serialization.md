# TASK 03.0 — BTCX invoice snapshot timestamp compatibility

The BTCX snapshot parser now accepts `rateTimestamp` as an ISO-8601 date/string or as an integer timestamp in Unix seconds, milliseconds, microseconds, Unix-epoch ticks, or .NET ticks. Integer units are recognized by their magnitude and range-checked. New prompt snapshots write one canonical UTC ISO-8601 round-trip string (`O` format). This keeps old snapshots readable while preventing a Greenfield payment-method retrieval from failing on the previously observed integer token.

The converter is scoped to the BTCX snapshot property; it does not change BTCPay serialization or core behavior. Tests retain and verify all other snapshot fields while reading each supported legacy numeric representation and writing the canonical string. The isolated development runtime smoke now exercises PostgreSQL-backed Greenfield invoice retrieval with `includePaymentMethods=true`; the endpoint returns the BTCX address/payment link without a timestamp deserialization error. The smoke validates Greenfield retrieval with mock RPC in ordinary gated configuration; the development acceptance run also exercised it against the isolated PoCX regtest wallet RPC.
